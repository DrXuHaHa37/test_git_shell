# 关节约束参考：Tianji 机械臂 & ApexHand 灵巧手

> 本文是 `mcap_precheck` ⑤ 关节类别（`joint`）的**限位与速度阈值来源说明**。
> 配置落地在 `apis/config/mcap_precheck.yaml`；本文解释数值**从哪来、实测是多少、怎么更新**。
>
> **每个指标都给出两类数值，请对照阅读：**
>
> | 类别 | 含义 | 来源 |
> |---|---|---|
> | **结构上限** | 机械/固件标称约束，越界即硬件异常 | URDF（手）、MJCF（臂） |
> | **实测标定值** | 真实录制的统计分布，用于设阈值 | 4 批 MCAP 录制（§5） |
>
> 单位：**位置 rad、速度 rad/s**。

### 2.4 耦合关节（21 → 16）

实测可确认 **5 对关节位置与速度完全相同**（表中 idx 3/4、7/8、11/12、15/16、19/20 数值逐位一致）：

```
thumb_j3 ≡ thumb_j4    index_j2 ≡ index_j3    middle_j2 ≡ middle_j3
ring_j2  ≡ ring_j3     pinky_j2  ≡ pinky_j3
```

21 − 5 = **16**，正对应 `openpi_client.rysen` 的 `hand_21_to_16` 与 `ACTION_DIM=46`：

```
46 = 双臂 7×2 (=14)  +  双手 16×2 (=32)
```

**含义**：耦合关节限位相同，独立检查不会误判；但同一异常会在两个 idx 上**同时报出**，看日志时属同一事件（§5.2 右手 92 = 6 + 43 + 43 即由此而来）。

### 3.3 结构速度上限缺失的原因

| 事实 | 证据 |
|---|---|
| MJCF 不含速度约束 | `marvin_L.xml` 全部 `<joint>` 只有 `range` 与 `actuatorfrcrange` |
| SDK 只暴露百分比接口 | `MarvinSDK.h:314-315`：`SetJointMode(arm, velRatio 0~100, accRatio 0~100)`；注释说明 **PVT 与拖动不受此限制** |
| 绝对限值运行时下发 | `AxisPln.h:65-66`：`m_Joint_Vel_Lmt[7]` / `m_Joint_Acc_Lmt[7]`，经 `OnSetLmt(dof, PosNeg, PosPos, VelLmt, AccLmt)` 填充 |
| 控制程序只用两档 | `realtime_arm_controller.cpp`：阻抗模式 `(100,100)`；位置/回零模式 `(20,20)` |

→ tianji 速度阈值**只能实测标定**，无结构上限可对照。

## 4. 三个容易踩的坑

### 4.1 `teleoperation/` 下的 ApexHand URDF 与 SDK 不一致

| 位置 | 用途 | 与 SDK 差异 |
|---|---|---|
| `sdk/config/*.urdf` | **权威** | — |
| `.../mink/examples/apex_hand/*/*.urdf` | MuJoCo IK | ❌ `velocity=0`<br>❌ `thumb_j0` 上限 1.5707（90°），SDK 为 1.3963（80°） |
| `apexhand_rgbd_retargeting/assets/.../*.urdf` | dex-retargeting | 同上，命名用 `right_thumb_j0` 体系 |

对 IK/retargeting 无影响（不用速度限），但做预检查会导致：速度限 0 → 任何运动都判超限；拇指上限放宽 10° → 漏检。**一律以 `sdk/config/*.urdf` 为准。**

### 4.2 `joints` 按 topic 解析，手/臂同段共存

关节规格（`defaults` / `joints` / `thresholds`）写在 `joint.topics[*]` 内，或用
`group` 引用 `joint.groups.<name>`；`_joint_spec()` 只按**该 topic 生效的规格**匹配 index。

```yaml
joint:
  topics:
    - {name: "/recording/apexhand/left/joint_states",  group: apexhand}
    - {name: "/recording/apexhand/right/joint_states", group: apexhand}
    - {name: "/tianji/joint_states",                   group: tianji_arm}
  groups:
    apexhand:   {defaults: ..., joints: [21 个], thresholds: {...}}
    tianji_arm: {defaults: ..., joints: [14 个], thresholds: {...}}
```

`/tianji/joint_states`（14 维）与手部（21 维）的 index 0 含义不同，但分属不同 group，
**互不覆盖**。手、臂同属 `joint` 一类，在同一个 profile 内一起检查：

| profile | joint 配置 | 运行方式 |
|---|---|---|
| `default` / `strict` | ApexHand 21 维 + Tianji 14 维 | `--profile default` |

⚠ 曾经的 `arm` profile 已删除；旧命令里的 `--profile arm` 改用 `default` 即可。

**子集录制**：允许只有左手 / 只有机械臂等不完整构型。`integrity.required_topics` 已置空，
缺失的 topic 在 ②⑤ 记为 `SKIPPED`（不阻断），因此单侧录制判定 `OK`。
代价：无法再自动发现「本该有右手却整批丢失」——需要时按录制批次另行核查。

### 4.3 `max_velocity` 对单点噪声极敏感，不要用作 error

实测（4 批，每手 7264 样本）：

| 指标 | 手部 | 臂部 |
|---|---|---|
| `velocity_p95` | 0.07 ~ 0.98 rad/s | 0.12 ~ 0.82 rad/s |
| `v_max` | 1.03 ~ **26.17** rad/s | 0.36 ~ 1.24 rad/s |
| `v_max / v_p99.9` | 可达 2~19 倍 | ≈ 1.0~1.1 倍 |

已排除时间戳抖动（dt 恒为 10.00 ms；消息自带 `velocity` 与差分速度量级一致）。

- **手部**：`v_max` 远超结构上限 8.7266，但属传感器单点跳变 → `max_velocity` 只能 `warn`，以 `velocity_p95` 作 `error`。
- **臂部**：分布干净（`v_max ≈ v_p99.9`，无尖峰）→ `max_velocity` 可用，但仍无结构上限可对照，暂定 `warn`。

### 5.2 ⚠️ 右手实测越界（92 次）—— 需确认

| 关节 | 越界次数 | 占比 | 实测极值 | 结构限 | 超出量 |
|---|---:|---:|---|---|---|
| `thumb_j0`（idx 0） | 6 | 0.083% | 1.4003 | 上限 1.3963 | +0.0040 rad（0.23°） |
| `pinky_j2` / `pinky_j3`（idx 19/20，耦合） | 43 + 43 | 0.59% | −0.1768 | 下限 −0.0873 | −0.0895 rad（5.1°） |

**两条独立证据指向"传感器噪声"而非"真实超限"**：

1. 同批数据中其余手指的对应关节（`index_j2` −0.049/−0.021、`middle_j2` 0.091/0.023、`ring_j2` 0.116/−0.031）**均在限位内**，只有 `pinky_j2/j3` 严重越界。
2. `pinky_j2/j3` 同时是**速度尖峰最大的关节**（`v_p99.9`=13.66、`v_max`=26.11，为全场最高）。位置越界与速度尖峰**同一关节共现**，典型的编码器噪声特征。

**当前行为**：`out_of_range_count: {max: 0, severity: error}` → 含该右手的录制会被判 **REJECTED_METRIC (20)**。

**这是检测生效，不是误报**，但需要你决定后续：

| 选项 | 适用场景 |
|---|---|
| 保持现状（`error`，拒绝） | 认为编码器噪声属数据质量问题，应拦截 |
| 降级为 `warn` | 暂不阻断流程，先积累更多批次观察 |
| 引入容差（如允许 ≤0.1% 越界） | 需新增"越界占比"指标，当前代码不支持 |

### 5.3 臂部速度标定说明

臂部无结构速度上限（§3.3），当前 3.0 / 2.0 均为**实测经验值**，基于 4 批同类型任务。
不同任务（如快速搬运）速度会显著更高，**换任务类型后必须重新标定**。

     "data/mcap_files/<录制目录>/*.mcap" --profile default
